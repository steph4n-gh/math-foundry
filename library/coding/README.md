# Binary neighborhood codes and unique-neighbor expansion

These are known foundational coding facts proved against the pinned genuine Mathlib. They concern the binary code `C(G)=ker(A_G)` over `ZMod 2`, with variable and check nodes represented by separate copies of the graph's vertices. This is the Tanner bipartite double cover of the graph, not a selected bipartition of its vertices. The code length is the graph order n. Its dimension is the GF(2) kernel dimension, and its distance d is the least nonzero codeword Hamming weight. When the kernel is zero, d is explicitly defined as the finite sentinel n+1, including d=1 for the vertexless graph. Always inspect dimension before treating a distance bound as evidence of a nontrivial code.

The unique-neighbor radius u is the minimum size of a nonempty stopping set minus one. A stopping set is a variable set for which no check has exactly one neighboring variable in the set. If no stopping set exists, the minimum uses sentinel n+1 and u=n. Thus every nonempty variable set of size at most u has a unique neighboring check. This is a precise combinatorial expansion quantity; it is not the normalized-Laplacian gap or a claim that the graph is a spectral expander.

`unique_neighbor_obstruction.lean` proves the central parity mechanism: if a check touches a nonzero word's support at exactly one coordinate, its parity sum is that nonzero coordinate and cannot vanish. This small theorem explains why unique-neighbor expansion constrains codeword support, using native `ZMod 2` arithmetic and finite neighbor sums.

`unique_neighbor_distance.lean` proves u+1≤d for every finite graph. Every nonzero kernel vector has a nonempty support with no unique neighboring check, so the smallest stopping-set size is at most the smallest nonzero codeword weight. The explicit sentinels handle zero codes and empty graphs without silently adding assumptions. This is the substantive expander-to-code bridge used by the focused campaign; it is a familiar mathematical mechanism, not a novelty claim.

`erasure_recovery.lean` proves a genuine recovery guarantee: two codewords in the binary adjacency kernel that agree outside an erased set S of size at most u must be equal. Their difference would otherwise be a nonzero codeword of weight at most |S|, contradicting u+1≤d. The source includes the distance theorem so it compiles independently of local helper modules. This certifies uniqueness of the mathematical completion. The Python peeling decoder is separately tested; its implementation is not formally verified, and peeling can stop beyond u even when a unique completion exists.

`parity_code_dimension_le_order.lean` proves that the kernel dimension is at most n, because the code is a subspace of the n-coordinate binary vector space. Dimension measures how many independent information bits the code can carry and helps distinguish nontrivial codes from zero-code distance sentinels. `nonzero_parity_code_distance_le_order.lean` proves d≤n under the explicit positive-dimension premise: a nonzero codeword exists and has at most n nonzero coordinates. Removing that premise is false, for example for the code of a single-edge graph.

`unique_neighbor_radius_nonnegative.lean` proves u≥0. Isolated variables give u=0, while an invertible adjacency matrix can give d=n+1. This sanity fact accompanies the substantive distance and recovery theorems; it is not counted as a discovery.
