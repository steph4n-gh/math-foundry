# Baseline and GitHub preparation

The clean project separates source, checked mathematical artifacts, baseline evidence, and new runtime output. The original research archive is not part of this distribution. Preserve its historical audit independently rather than copying unsupported claims into the current library.

The source-controlled mathematical seed consists of seven checked foundation sources in `library/` and 23 distinct replayable boundary examples in `seed/counterexamples.json`. Runtime initialization resets the research run history; it preserves mathematical knowledge rather than the previous cumulative atlas. The evaluator selects the common three checked starting bounds and excludes the training answers from either arm.

For a frozen baseline, retain the exact source commit, Python environment, Lean toolchain, Mathlib revision, test results, independent proof replays, challenger reassessment, controlled proof-transfer manifest and comparison, clique oracle report, authentic input hashes, paired timing records, and the measured negative results. Record relocated proof sources and receipt paths explicitly. A source-only copy or a passing import does not establish that the moved proof library works.

## Results with bounded meaning

The foundational graph inequalities are known results. Both reversed-order baseline trials certified six of six selected held-out consequences in the learning arm, versus two of six in the frozen arm. Replaying counterexamples can also move later refutations into a cheaper stage. Neither outcome establishes general recursive improvement or mathematical novelty.

The additional degree and edge clique ceilings are sound, but the existing greedy-coloring ceiling dominated them in the independent candidate-subset checks. Their final bounded paired benchmark produced a completed-pair geometric mean speedup of 0.883, indicating overhead rather than useful pruning. Keep the switch disabled and preserve this negative result as a baseline constraint for subsequent solver work.

Archived reports describe the exact code and measured environment identified by their hashes. Fresh qualification must identify the current checkout. Reports copied from an earlier location remain historical evidence until explicitly reconciled; old absolute receipt paths cannot silently establish current certification.

## Preparing publication

Before a GitHub release, inspect the complete tracked snapshot and its history, exclude credentials and mutable runtime data, verify source and data provenance, and test an independent checkout of the exact proposed commit. Keep source, tests, pinned manifests, proof explanations, and a small reviewable baseline evidence set together. Ignore the downloaded `.lake` runtime, caches, virtual environments, exploratory runs, and generated benchmark output.

The public research preview is at https://github.com/steph4n-gh/math-foundry under Apache-2.0 for original project code and proof sources. DIMACS graph bytes are omitted; provenance references do not establish redistribution permission. Downloaded dependencies, raw model requests and private historical archives are excluded. See [publication scope](publication.md) and [negative results](negative-results.md).

Subsequent work should be a separately measured change against this baseline. Candidate-directed graph synthesis, counterexample shrinking, rigorous interval certificates, broader formalization, and selective OpenAI theorem imports remain future stages, not capabilities of the frozen implementation.
